# Cyanyi Drama

Cyanyi Drama 是面向 AI 漫剧和短剧创作的 Web 工作台。它把文本创作、角色与场景资产、分镜、镜头、声音和成片交付放在同一个项目流程里，也提供独立的 AI 对话与媒体生成入口。

> 项目仍在持续开发中。生产结果依赖管理员配置的模型、服务商权限和账号额度。

## 功能概览

- **AI 对话与媒体生成**：通过可配置渠道使用文本、图片和视频模型。
- **漫剧项目工作区**：按编剧、资产、分镜、镜头、声音、交付六个阶段管理项目。
- **工作流与任务管理**：展示执行进度、失败原因和 Trace；支持暂停、恢复、取消和重试。
- **项目资产管理**：组织角色、场景、道具、分镜与媒体素材，并记录素材来源和所属项目。
- **渠道和模型配置**：按渠道维护 Base URL、API Key、模型及媒体能力；模型列表来自服务商接口。
- **账号与管理功能**：支持匿名 Session、邮箱密码、可选邮箱验证码，以及 GitHub 和 LinuxDO OAuth；管理员可配置系统渠道、登录方式和计费。
- **中英文界面**：应用提供中文和英文界面文案。

| 路径 | 用途 |
| --- | --- |
| `/` | 产品首页 |
| `/chat` | AI 对话、图片与视频生成 |
| `/projects` | 漫剧项目列表 |
| `/projects/:projectId` | 项目制作工作区 |
| `/login` | 登录和注册 |
| `/admin` | 管理员工作区 |

项目工作区会把剧集、制作阶段和当前选择保留在导航状态中。完成账号注册时，当前浏览器的匿名项目数据会迁移到新账号。

## 项目制作流程

导演助手、六阶段工作台和无限画布共用同一个项目、剧集、资产库及任务系统。

六阶段按实际产物补缺，不需要将策划包里的内容重新生成一遍：

| 阶段 | 复用内容 | 后续操作 |
| --- | --- | --- |
| 编剧 | 已采用的制作稿、场次与资产关联 | 审阅和编辑；改写、重新整理为可选操作 |
| 资产 | 人物传记、场景/道具设定与图片提示词 | 上传或生成形象图片并采用；批量设计默认跳过已有设定 |
| 分镜 | 已生成原创剧集的场景、镜头描述与图片/视频提示词 | 导入为待审核草案，检查时长、拆镜、连续性后确认；AI 重新拆镜为可选操作 |
| 镜头 | 同一分镜的提示词和资产参考 | 生成或上传实际图片/视频、选择版本；编辑提示词可直接保存 |
| 声音 | 剧本对白/旁白、角色声线与已有配音设计 | 补齐缺失的表演设计，绑定声线并生成音频/口型 |
| 交付 | 已采用的视频、声音与既有剪辑时间线 | 更新素材引用，预览并输出成片；重建时间线需要确认 |

新策划包采用时，会在同一事务中同步首集结构化场次、分镜草案、图片/视频提示词及台词，不额外调用模型。已生成原创正文但尚未开始结构化制作的剧集，在打开工作台时自动同步，兼容旧版正文排版；编剧侧栏也保留“同步已有场次、提示词与台词”入口。已编辑或已有下游制作记录时不会覆盖现有工作。后续集最初保存逐集大纲，可逐集续写；场景级草案需要人工检查，不能自动视为完整导演镜头设计。

新生成的原创首集和 AI 分镜共用制作设计契约：摄影（机位、焦距、构图、灯光、景深、色调）、逐角色表演、起始状态、连续动作节拍、世界约束以及按需生成的 VFX/SFX 时间点，直接存入现有分镜编辑器字段。原创场次草稿统一为 15 秒，与五段视频提示词时间线一致；模型输出会检查节拍覆盖、角色覆盖和特效时间范围。没有特效的镜头允许空列表。旧策划包兼容读取，但此前未生成的参数不会自动补造，也不会覆盖已确认的分镜。

- **小说入口**：上传并预览章节/分卷索引，确认后创建正式剧集和原稿版本，不自动改编全书。可勾选“导入后建立原著改编资料”，后台提取故事概要、人物、场景、道具与世界规则；从左侧故事资料查看、提交审核。它是基于原文的资料包，无需重新创作原创策划包。改编由用户点击或向导演助手明确提出，候选版本确认后才切换生产稿。
- **长篇处理**：AI 拆集、原著资料提取、长集改编按约 12,000 字符分段执行，保存中间结果与进度；资料分层合并，导演助手只读取有限详情。失败可通过任务重试继续复用中间结果。AI 拆集先在后台执行，再返回可调整的预览；分段边界需要人工审阅。这是字符预算，不保证所有模型的上下文容量；更长原著可按分卷选取范围导入。
- **原创入口**：剧本设定器分阶段流式生成大纲、资产档案、逐集规划和第 1 集正文。左侧导航可查看各部分；“确认采用并进入制作”创建缺失剧集和资产，已有正文与资产保留。第 2 集及以后可在写作页点击“续写本集正文”，或向导演助手提出“续写第 N 集”；必须已有采用的策划和上一集正文。续写依据本集大纲、人物/世界设定及前集实际结尾生成正文与制作设计，并单独补全本集出场且缺少规范的资产视觉档案；已有资产的非空设定保留。空白且无下游制作的集同步场次、分镜、提示词与台词草案；已有正文则保存为候选版本，等待采用。

以上后台任务需要 Redis 与独立 `pnpm worker` 进程运行；仅启动 Web 服务不会执行任务。资料和制作草案仍须审核，图片、视频、音频需另外生成或上传。
- **继续本集前期制作**：补齐缺失的场次整理、分镜、台词分析和配音设计；已有结果跳过。导演审核未通过时阻塞配音设计，请在分镜页确认问题后重试相应任务。
- **镜头制作**：工作台和关联镜头的画布节点共用生成与采用服务。新结果先作为候选，明确采用后才替换正式素材，重新生成不清空已选版本。
- **整集无限画布**：空白画布会接入本集已保存的分镜，按剧集顺序建立剧情因果主链，并把每个角色、场景和道具只连到首次出现的镜头，减少重复线。上一集片尾与本集开场出现相同角色或道具时，会增加一条“承接上一集”线；这表示可见的连续线索，不自动推断剧情因果。已有画布可用“生成整集因果图”补齐关系。整集图采用独立布局；从底部添加节点会放在空位，不会重排镜头和因果线。素材关联只用于表达剧情归属，生成图片/视频仍需显式添加参考连线。独立节点仍可用于试验；关联镜头节点读写正式镜头数据。
- **配音**：重新分析和分镜同步按说话人、内容及发声方式匹配台词；未变化的台词保留音色、表演设计和已生成音频。
- **交付**：已采用镜头变化时提示更新素材引用，保留剪辑顺序、时长和裁剪；分段结构变化需要重新编排。重建时间线须明确确认。

所有生成结果均属于当前项目。阶段完成度来自正式制作对象与已采用素材，任务列表仅用于查看执行进度。项目助手保留最近对话的本地浏览器副本；刷新后待审批操作不会恢复，须重新提出操作。

## 本地运行

### 环境要求

- Node.js 20 或更高版本
- pnpm（版本见 `package.json` 的 `packageManager`）
- Docker 和 Docker Compose

### 启动依赖服务

```bash
pnpm install
docker compose up -d
```

Compose 会启动本地 PostgreSQL 和 Redis。复制环境变量示例：

```bash
# macOS / Linux
cp .env.example .env.local

# PowerShell
Copy-Item .env.example .env.local
```

本地示例配置使用 Compose 的数据库地址。生产环境必须设置唯一且高强度的 `APP_SECRET`，并使用自己的 `DATABASE_URL`、`REDIS_URL` 和 `APP_BASE_URL`。

### 初始化数据库并启动

```bash
pnpm exec prisma migrate deploy
pnpm dev
```

打开 [http://localhost:3000](http://localhost:3000)。

图片、视频、声音生成和后台工作流需要单独运行 Worker：

```bash
pnpm worker
```

开发时保持 Web 应用和 Worker 使用相同的数据库、Redis 与应用密钥配置。

原著资料分析、长篇改编依据提取和 AI 分集默认使用 6 路并发，并按原文顺序组织结果。通过 `.env.local` 的 `SOURCE_ANALYSIS_CONCURRENCY` 设置 1–8 路并发；`MANUSCRIPT_ANALYSIS_CONCURRENCY` 可单独覆盖原著资料分析（修改后重启 Worker），每个任务独立应用此限制。模型或渠道限流时可调低。已保存分段可在暂停恢复或失败重试后复用；同一用户、项目、原著版本、模型和渠道的历史分块笔记也可复用。提取使用专门的简洁资料提示词，同层合并最多 6 份并受输入长度限制。并发主要缩短等待，历史笔记复用减少重复 Token；首次完整分析仍需读取全书，实际耗时与用量取决于服务商响应及输出。

## 模型与服务配置

启动后，在应用设置中配置模型渠道的协议、Base URL、API Key 和模型；管理员还可以在管理工作区配置系统渠道、注册登录方式、SMTP 和支付服务。密钥只在服务端使用，读取设置时不会返回密钥原文。

常用环境变量：

| 变量 | 用途 |
| --- | --- |
| `DATABASE_URL` | PostgreSQL 连接地址 |
| `REDIS_URL` | Redis 地址，供任务队列及登录限流使用 |
| `APP_SECRET` | 加密服务端配置等敏感数据；生产环境必填 |
| `APP_BASE_URL` | OAuth 回调和对外链接使用的应用地址 |
| `AI_GATEWAY_API_KEY` | 可选的 AI Gateway 凭据 |
| `EMAIL_*` | 可选的邮箱注册验证码和 SMTP 配置 |
| `GITHUB_*`、`LINUXDO_*` | 可选的 OAuth 环境变量回退配置 |
| `EPAY_*` | 可选的易支付环境变量回退配置 |

完整变量清单及默认值见 [.env.example](.env.example)。使用 OAuth 时，服务商回调地址应配置为：

```text
{APP_BASE_URL}/api/auth/oauth/github/callback
{APP_BASE_URL}/api/auth/oauth/linuxdo/callback
```

服务商密钥也可以从管理员设置页维护。系统设置保存到数据库后，数据库中的启用状态优先；未填写的凭据仍可使用环境变量回退。

## 后台任务和数据

Web 应用负责接收请求、读写业务数据并创建任务。Redis/BullMQ 负责排队和任务事件，Worker 执行媒体生成及耗时工作流。任务状态、用量和媒体内容保存在 PostgreSQL；应用不会用伪造结果代替未配置或失败的服务商调用。

用户、匿名 Session、渠道、项目、工作流和媒体任务都保存在数据库。会话使用 HttpOnly Cookie；密码使用 scrypt 哈希；Session 凭据以哈希形式保存。OAuth 流程使用短期 state 和浏览器绑定 Cookie。登录尝试通过 Redis 按邮箱失败次数和客户端 IP 限流。

数据库结构变更通过 Prisma migration 管理：

```bash
# 开发时创建并应用迁移
pnpm db:migrate

# 部署时应用已提交的迁移
pnpm exec prisma migrate deploy

# 更新 Prisma Client
pnpm db:generate
```

`pnpm db:reset-business` 默认只预览重置范围；只有确认要清除业务数据时才追加 `-- --execute`。该脚本会保留管理员账号和系统渠道配置。
